# CanvasプレビューとMP4出力

## 描画

`web/canvas-renderer.js` の `CanvasRenderer` をプレビューとMP4出力が共有する。
出力解像度で描画し、プレビューのCanvasはCSSで縮小する。設定変更・編集・シーク時に
同じ `renderFrame(time)` を呼ぶ。既存のPillow APIは互換性のため残すがGUIでは呼ばない。

- 背景は黒、画像指定時はアスペクト比を維持した中央cover配置。
- 立ち絵の原点は画面中央、画像中央をX/Yへ配置し拡大率を適用。PNGのアルファを保持。
- 発話区間は `[start, end)`。重複発話は全員カラー、無発話時は全員グレースケール。
  設定スロットはマッピング後の話者名をソートした順番で、EXOと共通。
  連番でない話者番号や手動の話者名にも対応する。
- 字幕は同時に有効なセグメントを元の配列順に重ねる。共通座標の字幕は重なるため、
  必要に応じてセグメント時刻を編集する。AviUtlの別話者レイヤーと同じ重なり方になる。
- フォント、太字、斜体、文字色・縁色、縁取り、字間・行間、9方向の基点、X/Yを適用。
  縁取りはCanvasのround stroke（太さはフォントサイズの1/12、最低2px）。
- `max_chars_per_line` はUnicodeコードポイント数で折り返し、明示改行と空行を保持。
- `display_speed=0` は全文表示。正の場合は1秒あたりの文字数として、開始から
  `floor((time-start)*display_speed)` 文字を表示。改行は文字数に含めず、全文の配置を
  固定して文字だけ増やす。既存のPillowプレビューで無視されていた設定も反映する。
- 指定画像・フォントの不足は明示的なエラー。WindowsのTTCに含まれるフォント名は
  `&` で分割して一覧化。旧設定の集合名は先頭のフォントファミリーとして解決する。
- 画像・フォントは初期化時に読み込み、フレームごとのファイル取得は行わない。
  GIFなどのアニメーション画像は先頭フレームを静止画として使用する。
  時刻指定のAPIは音声プレイヤーの `currentTime` からも呼び出せる。

## 時間・音声

EXO設定の `width` / `height` / `fps` を共用する。初期値は1920×1080 / 30fps。
設定・プロジェクト・Undo/Redoにも同じ既存フィールドを保存するため、`.awproj` は
従来のversion 1のまま。旧ファイルにフィールドがなければ初期値を適用する。
音声ソースと出力先は書き出しごとの選択であり、プロジェクトには追加しない。

MP4は字幕も音声も0秒基準。EXO専用の `audio_start_seconds`、BGM、ジングル、
クロージング画像・延長区間は適用せず、出力画面にもこの差を表示する。
EXO出力の動作・素材参照・開始オフセットは変更しない。

| ソース | 動作 |
|---|---|
| 元音声 | 元ファイルの全尺を0秒から使用。解析用16kHz WAVではない |
| 結合TTS音声 | 既存manifestと設定から有効な生成済み音声を取得し、各セグメント／チャンクの最初の字幕の開始位置へ配置。重複はミックス |
| 無音 | 音声トラックなし |

TTSは現在のテキスト・話者・設定に対応する音声が全件揃っていなければ停止する。
ネットワーク生成は呼ばない。TTSの結合WAV保存が行う「隙間を詰める連結」や
`combined_wav_silence_ms` の追加は行わず、字幕の既存タイムスタンプを維持する。
チャンク内の各字幕の時刻は変更しないため、チャンク内の発話の厳密な頭出しは
利用者が字幕のタイムラインで調整する。重複音声の和は[-1,1]でクリップする。

動画の内容尺は `max(字幕の最終終了, 全音声クリップのstart+実際の音声尺)`。
総フレーム数は `ceil(内容尺*fps)`、最低1フレーム。
フレーム時刻は常に `frameIndex/fps`、動画尺は `総フレーム数/fps`。
音声が短い場合は動画末尾まで無音を補い、長い場合は最後まで映像を延長する。
末尾のフレーム丸めによる延長は1フレーム未満。AAC自体のパディングはコーデックの
フレーム単位の差として生じる。`requestAnimationFrame`や実時間に尺は依存しない。

## エンコードとI/O

[Mediabunny](https://mediabunny.dev/guide/writing-media-files) 1.65.1の
`CanvasSource` / `AudioSampleSource` / WebCodecsを使用。
H.264は1920×1080/30fpsで8Mbpsを基準に解像度・fpsで比例調整し、AACは
48kHzステレオ192kbps。音声はJSで固定サイズのPCMブロックへ変換し線形リサンプリング。
コーデック・解像度・fpsの対応を実際の設定で検査してからファイルを開く。
無音出力はH.264のみ検査する。コーデックの自動変更はしない。

MP4はfragmented形式。`StreamTarget`で最大256KiBずつPythonへ渡し、各フレーム、
音声ブロック、書き込みをawaitしてバックプレッシャーを伝播する。
フレーム列、全PCM、完成MP4の全体バッファを保持しない。音声を映像と交互に供給し、
一方のトラックを全件先行投入してmuxerへ蓄積しない。
音声入力のURLキャッシュは各1MiB、同時に開くTTSは最大32クリップ。
この上限を超える重複はエラーにする。

WebView2ではFile System Access APIの存在を実行時に記録するが、保存はネイティブ
ダイアログとPythonブリッジへ統一する。ブラウザ側の保存許可や既存ファイルへの
途中書き込みに依存せず、出力先限定とatomic replaceを保証するためである。

- 読み取り: 127.0.0.1の一時ポート、ランダム256-bitトークンで登録されたファイルのみ。
  HTTP Rangeに対応し、URLから任意パスへアクセスできない。
- 書き込み: ネイティブ保存ダイアログで選択した出力先をランダムトークンへ紐付ける。
  JSからパスを指定する書き込みAPIはない。
- チャンクBase64は最大256KiBのデータに限定。サイズ、順序、オフセットを検証する。
- 同じディレクトリの `.mp4.part` に書き込み、muxerのfinalizeとfsync後にのみ
  `os.replace` で選択先を置換し成功を表示する。既存動画はそれまで保持する。
- キャンセル・エラーではエンコーダー、デコーダー、画像を解放して一時ファイルを削除。
  書き出し中のウィンドウ終了はキャンセルを要求して終了を一旦止める。中止後に再度閉じる。
- OSによる強制終了・電源断では `.mp4.part` が残る場合があるが、完成名では公開しない。
- 完了したファイルは同じ読み取りサーバーでアプリ内のvideo要素へ渡し、再生確認できる。

## ビルドと検証

```powershell
npm ci
npm run build
npm test
uv run pytest tests/ -m "not e2e and not slow" -q
uv run pytest tests/e2e/ -m "e2e and not slow" -q
uv run pytest tests/e2e/test_video_export.py -k ten_minute -q
uv build
uv run pyinstaller build.spec --noconfirm
```

JSのロックファイルと生成済み `web/vendor/video-tools.js`、ライセンスを同梱する。
配布後はnpm・開発サーバー・CDN不要。PyInstallerはwebディレクトリを丸ごと同梱する。

`tests/e2e/test_video_export.py` は実WebView2で出力し、ffprobeでトラック・fps・尺を
検査する。FFmpegはテストのデコードとフレーム抽出だけに使用する。
元音声とTTSの音声パルス位置、日本語字幕、重複・空白区間、Canvasとの差、
完成動画のアプリ内再生、キャンセル、設定不正・画像・フォント・TTS不足を検証する。
ネイティブファイルダイアログの回答だけをテスト用ランチャーで置き換える。
本番のJSエンコード、素材HTTP読み取り、Python書き込み処理はそのまま通す。
日本語の描画にはロックファイルで固定した開発依存のNoto Sans JPをテスト内で読み込み、
CIサーバーへのMeiryoインストール有無に依存しない。MP4 E2Eの前には `npm ci` が必要。
プレビュー初期化エラーは `preview-diagnostics.json` に保存して即座に報告する。

10分の計測は160×90/30fps・音声ありの18000フレームを実出力し、GC後のJSヒープを
複数時点で記録する。1080pで10分のGPU/ネイティブメモリ計測ではない。
検証動画、抽出フレーム、ffprobe結果、メモリ記録は `test-results/video/` に保存する。

## 制約

- WebView2のWebCodecs H.264/AAC対応が必要。GPU・Runtimeごとの差は事前検査で表示する。
- WMAはJS側の入力コンテナに非対応。元音声をWAVに変換して読み込み直す必要がある。
- Canvas字幕はAviUtlと同一ピクセルではない。AviUtlの制御文字は解釈せず文字として描画。
- EXO向けのBGM・ジングル・クロージング演出はMP4に未対応。
- File System Access APIの実際の保存許可フローは使用・検証しない。
